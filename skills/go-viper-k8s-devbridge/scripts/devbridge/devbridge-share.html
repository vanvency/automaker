Local source / remote cluster

后端留在本地， 上下文留在 K8s。

Devbridge 让你的 Go 源码直接进入授权的非生产集群上下文：继承目标 Pod 的 DNS、环境变量、出站网络和只读挂载，同时只把带随机会话标识的请求引到你的进程。不改共享 Deployment，不构建业务镜像，不全局重写 Gateway。

Core idea

Devbridge 不是“又一个端口转发”

◈

mirrord 负责上下文

让本地源码进程拥有目标容器的 Kubernetes 环境：远端 DNS、服务网络、环境变量与只读挂载文件都能按需继承。

▤

Devbridge 负责工程化

封装构建指纹、SSH/产物传输、版本固定、会话路由、readiness 验证、rollout 重绑、退出清理和缓存复用。

◎

业务代码负责安全模式

CVAT 使用独立的 CVAT_DEVBRIDGE_API_ONLY 启动模式，跳过后台所有权与启动期变更，只挂载已审计 API。

前端永远不需要注入 X-Dev-Route。 本地 proxy 先剥掉调用方伪造的 selector，再只对 allowlisted 的 /cv/api/knowlhub/ 和 readiness 路径注入。业务响应的 X-Devbridge-Route 只用于验证 DEVBRIDGE_ROUTE_ID，防止把共享 Pod 的 HTTP 200 误判成本地代码接管。

Lifecycle

up 背后到底发生了什么

  1. doctor 预检

    检查本机工具、SSH、远端 Linux amd64、kubectl、Pod 创建 RBAC、agent 镜像传输能力、Gateway 可达性。Deployment 目标必须是恰好 1 个 Ready replica。

  2. 构建指纹与三层缓存

    指纹包含构建命令、Go 工具链/CGO 环境和当前工作区及本地 replace 仓库的 tracked/untracked 内容。命中则复用最终二进制、zstd 产物或远端 checksum 缓存。

  3. 传输固定版本运行时

    mirrord client/layer 按 SHA-256 校验，不支持 floating latest。两端都有 zstd 时压缩应用二进制，否则自动回退原始上传。

  4. 远端启动并继承集群视角

    开发进程在 dev17 独立目录运行，经 mirrord 连接目标容器视角。KUBERNETES_* 与远端 ServiceAccount 文件按需进入 in-cluster client。

  5. readiness 双重确认

    工具要求 /cv/api/devbridge/status 同时返回 HTTP 200 和正确 route ID。通过后才输出 devbridge ready。

  6. Pod rollout 自动重绑

    启动时记录唯一 Ready Pod 的 name/UID。远端退出后：原 Pod 仍健康则拒绝重复启动；原 Pod 消失、terminating 或不 Ready 才等待替代 Pod 并复用会话产物恢复。

  7. Ctrl-C 清理，保留缓存

    正常退出删除 agent Pod、远端 session 目录和本地活动状态。构建、压缩和 checksum-pinned runtime 缓存默认保留，加速下一次 up。

Safe mode

API-only 不是只读数据库模式

CVAT_DEVBRIDGE_API_ONLY=true 限制的是启动所有权：开发者主动调用写 API 时，业务写入仍然发生。它的目标是避免一个额外调试实例抢占后台任务、修改 schema 或重复恢复共享任务。

启动行为 普通实例 Devbridge API-only
连接现有 PostgreSQL / MySQL 是 是
创建 database / extension、主库 DDL、迁移锁 是 否
KnowlHub AutoMigrate / 索引补建 是 默认否；显式开关仅迁移 4 张 GraphRAG 控制表
MinIO bootstrap、points rule upsert、demo seed 是 / 按配置 否
task recovery、worker、cron、watcher、Redis subscriber 是 否
HTTP API 完整 /api/knowlhub/* + readiness

GraphRAG 迁移开关必须显式。 当前 `.devbridge.yaml` 为联调设置 CVAT_DEVBRIDGE_GRAPHRAG_MIGRATE=true；表结构补齐后应恢复为 false，重新回到零启动 DDL 模式。

不要再挂载完整 CVAT API。 实测中完整 API manager 的构造副作用启动过 asset task recovery，并 UPDATE 共享任务状态。新增调试模块前必须审计构造函数、singleton getter 和启动调用图。

Trust boundary

哪些内容会离开本地，哪些永远不会

可以上传 / 缓存

最终 Go 二进制、checksum-pinned mirrord client/layer、非敏感 app.sync 文件（当前只有 etc）。远端缓存目录不能是符号链接，文件必须 checksum 校验。

不会导出 / 缓存

Pod 环境变量、Secret 内容、mirrord session 配置和业务凭据。挂载 Secret 通过 mirrord 按打开动作从目标容器只读获取，不会 kubectl cp 到本机或 dev17 临时目录。

网络边界

proxy 只允许监听 loopback。浏览器不能传任意 upstream URL/IP；selector 只注入到 .devbridge.yaml 列出的最小公共服务前缀。

环境声明

remote.non_production=true 是工具运行前的显式安全声明。mirrord agent 需要 privileged capabilities 与 Pod RBAC，生产 namespace 应禁用。

Operations

常见信号与正确动作

ready 一直 404

检查 gateway 是否保留 X-Dev-Route、health path、remote/local port 映射和 agent 日志。不要为此把 route_paths 扩成整个服务。

migration lock not acquired

说明运行的不是 API-only 安全模式二进制，或 override 未生效。立即停止，不要继续等待共享环境上的迁移锁。

端口占用

本地 proxy 端口修改 gateway.listen；业务端口占用在 dev17 上，修改 app.local_port 和对应 Viper listen override。

HTTP 正常，实时链路异常

WebSocket、gRPC、HTTP2 和大文件上传要按业务协议单独验收。当前自动 readiness 只证明 HTTP route 已接管。

异常断开

Ctrl-C 正常退出；终端异常后执行 scripts/devbridge down，确认 agent Pod、session 目录和本地活动状态已清理。

什么时候清缓存

普通 down 保留缓存。只有显式失效或磁盘清理时才用 scripts/devbridge clean-cache。

Adoption

迁移到另一个 Go + Viper 项目

  1. 先找 Viper 初始化和 main 调用图

    不要复制 CVAT 的环境变量名或跳过清单。按项目的 Viper key 前缀实现独立的 <PREFIX>_DEVBRIDGE_API_ONLY。

  2. 审计启动副作用

    保留配置加载、现有数据库连接、请求处理所需 client 与无状态 API；跳过创建 database/extension、AutoMigrate、迁移锁、bucket 创建、任务恢复、worker、cron 和 watcher。

  3. 挂载最小 API 与 readiness

    在 API-only 模式挂载已审计模块和只存在于此模式的 readiness endpoint，让响应回显 DEVBRIDGE_ROUTE_ID。

  4. 分层验证，不接受“agent 起来了”

    运行工具单测、项目单测、真实服务 E2E；检查禁止启动动作的日志；调用一个真实读接口；最后验证退出清理。

One-line takeaway

后端拿到完整的集群上下文，
前端拿到稳定的本地 Gateway，
集群拿到的却只是一个短生命周期 agent。
